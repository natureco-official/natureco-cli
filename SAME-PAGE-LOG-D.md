### Integrator findings (Codex, verbatim)
- [FIX] `streamProviderCompletion` currently writes tokens directly to stdout and returns only a finished object, exposing neither incremental text/tool-call deltas nor cancellation -> Change it to accept a signal plus normalized delta callbacks or an async generator and remove all terminal writes from the API layer.
- [FIX] OpenAI tool-call fragments are accumulated internally and never exposed incrementally to `code_v5`, so D1 cannot drive the tool loop from the live stream -> Emit normalized `text_delta` and `tool_call_delta` events while still returning one canonical completed assistant message.

- [FIX] The streaming primitives currently own stdout, which makes the proposed single presentation writer impossible and can duplicate/interleave output -> Make provider streaming transport-only and route every visible byte through the writer.
- [FIX] Emitting a trailing partial block raw and later rendering it cannot be append-only and also equal `renderMarkdown(full)`, because already-emitted Markdown markers cannot be transformed in place -> Keep the active block in a repaintable TTY region and commit it only once its parse is stable, while using raw streaming on non-TTY.
- [FIX] Blank lines and closing fences are not generally safe Markdown commit boundaries because setext headings, lists, block quotes, tables, HTML, and reference definitions can reinterpret earlier lines -> Derive commit points from lexer-confirmed stable prefixes or explicitly constrain the supported incremental grammar and test every ambiguous construct.
- [CLARIFY] An unterminated code fence forces a choice between withholding its body indefinitely, showing it raw permanently, or repainting it at stream end -> Specify TTY repaint-at-finalization and non-TTY raw behavior, including interruption inside the fence.

- [FIX] `readline` remains attached while a turn runs, so separately enabling raw mode and listening to stdin risks duplicate Esc handling, swallowed keys, and a terminal left raw after rejection -> Pause readline, preserve the prior raw state, install exactly one keypress owner, and restore listeners/raw state in an unconditional `finally`.
- [FIX] Esc capability must be gated on stdin TTY while display capabilities depend on stdout TTY, but the plan treats TTY as one condition -> Define separate input and output capability gates so piped stdin/stdout combinations degrade correctly.
- [KILL] Detaching from a non-cooperative tool and marking it cancelled lets its filesystem/process side effects continue after the next prompt and may produce late cards or hooks -> Never detach; add real cooperative cancellation through the executor or wait for a non-cancellable tool to settle before returning control.

- [FIX] Interrupting a parallel tool batch can leave completed side effects with no committed results or leave sibling calls unresolved in history -> Define batch cancellation and commit policy that produces a provider-valid result for every retained tool call before the next request.
- [FIX] The shipped `Spinner` writes directly to stdout, emits text even on non-TTY, and only checks `CAPS.isTTY`, so reuse violates writer serialization and NO_COLOR suppression -> Give Spinner an injected writer/scheduler or move animation into the presentation writer with explicit `stdout.isTTY && NO_COLOR absent` gating.
